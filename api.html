FakeStoreAPI Referenceمرجع FakeStoreAPI

Every endpoint, the parameters you can send, the responses you get back, and a live Try it button. كل نقاط النهاية (endpoints)، والمعاملات التي يمكنك إرسالها، والاستجابات التي تعود إليك، مع زر "جرّب" حي.

Important: read before you tryمهم: اقرأ قبل أن تجرّب

  • FakeStoreAPI only simulates writes. POST, PUT, PATCH and DELETE return a believable response, but nothing is saved. Reload the data and it is unchanged. الـ FakeStoreAPI تحاكي عمليات الكتابة فقط. فطلبات POST وPUT وPATCH وDELETE ترجع استجابة تبدو حقيقية لكن لا شيء يُحفظ. أعد تحميل البيانات وستجدها كما هي.
  • A GET with a wrong id (for example /products/9999) can return status 200 with an empty body, not 404. Always check that you really got data. طلب GET بمعرّف خاطئ (مثل /products/9999) قد يرجع الحالة 200 مع جسم فارغ وليس 404. تأكد دائماً أنك استلمت بيانات فعلاً.
  • Login with wrong credentials returns status 401 and a plain text message, not JSON. تسجيل الدخول ببيانات خاطئة يرجع الحالة 401 مع رسالة نصية عادية وليس JSON.

What is an API?ما هو الـ API؟

Imagine a restaurant. You (the client, your web page) sit at a table. The kitchen (the server) has all the food (the data). You never walk into the kitchen: you tell the waiter what you want, the waiter carries your order to the kitchen, then brings the food back. The waiter is the API. The menu is this reference: it lists what you can order and how to ask for it. تخيّل مطعماً. أنت (الـ client، أي صفحة الويب) تجلس إلى الطاولة. والمطبخ (الـ server) فيه كل الطعام (البيانات). لا تدخل المطبخ أبداً: تقول للنادل ما تريد، فيحمل طلبك إلى المطبخ ثم يعود بالطعام. النادل هو الـ API. وقائمة الطعام هي هذا المرجع: تعرض ما يمكنك طلبه وكيف تطلبه.

Mini glossaryقاموس مصغّر

API
Application Programming Interface: a set of rules that lets one program ask another program for data. واجهة برمجة التطبيقات: مجموعة قواعد تتيح لبرنامج أن يطلب بيانات من برنامج آخر.
Endpoint
One specific address you can call, such as /products. Each endpoint does one job. عنوان محدد يمكنك استدعاؤه مثل /products. كل endpoint يقوم بمهمة واحدة.
HTTP method
The verb of the request: GET read, POST create, PUT replace, PATCH change a part, DELETE remove. فعل الطلب: GET قراءة، POST إنشاء، PUT استبدال كامل، PATCH تعديل جزء، DELETE حذف.
Path parameter
A value inside the path, written in braces: in /products/{id} you replace {id} with 5. قيمة داخل المسار مكتوبة بين أقواس معقوفة: في /products/{id} تستبدل {id} بالرقم 5.
Query parameter
An optional setting added after a ?, joined by &: /products?limit=5&sort=desc. إعداد اختياري يُضاف بعد علامة ? ويُفصل بـ &: /products?limit=5&sort=desc.
Request body
The data you send inside POST, PUT and PATCH requests (usually JSON). GET and DELETE have no body. البيانات التي ترسلها داخل طلبات POST وPUT وPATCH (غالباً بصيغة JSON). طلبات GET وDELETE ليس لها body.
JSON
JavaScript Object Notation: a text format for data made of {"key": "value"} pairs and [lists]. صيغة نصية للبيانات مكوّنة من أزواج {"key": "value"} وقوائم [lists].
Status code
A number the server sends back to say how it went (200 = OK, 404 = not found...). رقم يرسله الخادم ليقول كيف سار الطلب (200 = نجاح، 404 = غير موجود...).
Header
Extra information sent with a request or response, like Content-Type: application/json. معلومات إضافية تُرسل مع الطلب أو الاستجابة مثل Content-Type: application/json.
Token
A long secret string you get after logging in. It proves who you are on later requests (usually in a header). نص سرّي طويل تحصل عليه بعد تسجيل الدخول. يثبت هويتك في الطلبات اللاحقة (غالباً داخل header).

Your first requestطلبك الأول

Paste this in your browser console (F12) or in a script. await waits for the answer, then we turn the text into a JavaScript object. الصق هذا في console المتصفح (F12) أو في سكربت. الكلمة await تنتظر الإجابة ثم نحوّل النص إلى كائن JavaScript.

JavaScript (fetch) 
const response = await fetch('https://fakestoreapi.com/products?limit=2');
const products = await response.json();
console.log(response.status, products);
